# EXAONE C++ Build

This directory is the C++ subproject root.

```text
cpp/
├── CMakeLists.txt
├── main.cpp
├── include/
│   ├── exaone.h
│   └── parameters.h
└── src/
    └── exaone.cpp
```

The executable reads the default relative weight path from
`include/parameters.h`:

```text
weight/EXAONE-4.0-1.2B/model.bin
```

Run the executable from the repository root unless this path is changed.

## Linux

From the repository root:

```bash
cmake -S cpp -B cpp/build
cmake --build cpp/build
./cpp/build/exaone
```

From inside `cpp/`:

```bash
cmake -S . -B build
cmake --build build
cd ..
./cpp/build/exaone
```

The program asks for `tile size`. For the current experimental path, `64` is a
reasonable first value.

## Windows Command Line

Install CMake and a C++ compiler first. The simplest option is Visual Studio
2022 with the `Desktop development with C++` workload.

From the repository root in `x64 Native Tools Command Prompt for VS 2022`:

```bat
cmake -S cpp -B cpp\build -G "Visual Studio 17 2022" -A x64
cmake --build cpp\build --config Release
cpp\build\Release\exaone.exe
```

For a Ninja-based build:

```bat
cmake -S cpp -B cpp\build -G Ninja
cmake --build cpp\build
cpp\build\exaone.exe
```

## Windows Visual Studio

Visual Studio can open the CMake project directly.

1. Open Visual Studio.
2. Select `File > Open > Folder...`.
3. Choose the repository root or the `cpp/` folder.
4. Wait for CMake configure to finish.
5. Select the `exaone` target.
6. Build with `Build > Build All`.
7. Set the debugging working directory to the repository root.
8. Run `exaone`.

If Visual Studio is opened at the repository root, make sure it discovers
`cpp/CMakeLists.txt`. If it does not, open the `cpp/` folder directly.

## Build Artifacts

`cpp/build/` is generated by CMake and should not be committed.

To clean the local build output:

```bash
rm -rf cpp/build
```

On Windows PowerShell:

```powershell
Remove-Item -Recurse -Force cpp\build
```
